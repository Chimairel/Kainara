# Admin controls, cooking links and current-report acknowledgment

## Scope

- Cooking help opens a governed linked YouTube video where available; otherwise it opens a YouTube search for the dish. Article attribution remains separate. Reject non-YouTube/spoofed video links in the client fallback; the backend prioritizes recorded videos over articles.
- Existing staff password forms previously called a route behind USER-only middleware. Allow authenticated ADMIN/NUTRITIONIST own-account settings before that member gate, retaining the existing member prerequisites. Current-password verification, password rules and transactional refresh-session revocation stay in the existing service. Expose Admin profile in primary navigation and sign the administrator out after a password change.
- Add Admin → Nara answers → Submitted messages, with member identity, submitted text, command mode, date, explicit search and 25-record cursor pages. Backend role checks remain ADMIN-only. A read is audited without copying search terms or chat text into audit metadata.
- Introduce `AssistantMessageLog` through additive migration `20261020010000_nara_submitted_message_records`. Store only submitted text (up to 1,000 characters), owner, submission/request identity, mode and time. Do not attach unsent drafts, context arrays, model replies or account credential fields. Submitted text can itself contain personal data: disclose this in the composer and Privacy Policy and tell members not to send credentials. Existing declarations/consent versions are not silently rewritten.
- The normal message endpoint records validated submissions; local prepared help sends a separate best-effort recording request, without waiting, queueing offline text or admitting AI. Both use the same per-member request limit. Repeated confirmation/replay with the same owner/request key cannot create a duplicate. Text received under a reused key is not overwritten. Unsent typing, refresh and reply animation do not create records. Local help remains available if the recording network request fails; this is not a guaranteed-delivery or retroactive transcript system.
- Admin reads exclude records older than 30 days. The daily cleanup removes expired message rows even if Nara is disabled. Account export includes retained owned records; account deletion cascades to them. Clearing browser chat/signing out does not remove server records. Existing eight-day AI receipts and 24-hour browser sessions retain their separate purposes.
- Website media drafts gain optional `{fit,x,y}` framing. Older JSON keeps top-center cover framing. Offer cover/contain, horizontal/vertical sliders, reset and a draft preview. Persist validated numeric coordinates only (0–100), through the existing revision/audit/publish path. No image edit, re-upload or new dependency is required. Live publication is unchanged until Publish; video playback remains contained. Framing also applies when an image poster is rendered as a fallback.
- A selected historical report can no longer mark the live profile acknowledged when planning inputs differ. Weight/body/preference corrections return Home and require acknowledgment before planning again. Existing logged meals, snapshots and review decisions remain unchanged. Suppress stale generation notices/actions while showing the sleeping-Nara report hold. Same-input reports still use the established matching rules; this is not new clinical approval.
