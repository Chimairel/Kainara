# Catalogue source repairs — October 6, 2026

## Result

Applied to the explicitly checked development Neon database after a full run on a separate local copy: 240 source recipes, 209 recovered source ingredient identities across 186 recipes, 203 recovered imported-library ingredient identities and 238 invalidated/refreshed library variants. 56 source slot declarations were narrowed; 1 raw recipe lost incorrect diet tags. Two source recipes were retired pending nutrition/serving review.

18 unconsumed pending/approved plan snapshots referenced changed sources and were cancelled so stale ingredients cannot be approved or eaten. Dependent groceries were marked stale. This repair does not automatically regenerate or clinically approve replacement meals. Consumed/skipped logs and their historical nutrition/ingredient snapshots were preserved.

## Cause and fixes

1. The recipe parser treated food nouns as measurement units. For example, the omelet stored name `(beaten)`, unit `eggs`, quantity `1.5`, and the invalid-fragment cleanup excluded it from planning. The original recipe has three eggs for two servings. Recovery now restores the explicit food token, uses a count/strip unit, preserves the per-serving quantity, clears the invalid-fragment exclusion, and rematches FNRI only where an identity-preserving match exists. Import uses the same recovery before classification/signature calculation, preventing recurrence. It never invents eggs from a title. [Omelet source](https://panlasangpinoy.com/eggplant-and-ground-chicken-omelet/), [scrambled-egg source](https://panlasangpinoy.com/scrambled-eggs-with-sun-dried-tomato-and-bacon/), [squid source](https://panlasangpinoy.com/inihaw-na-pusit-grilled-squid/).

2. Shellfish plurals, crabmeat/pusit, named wheat pasta and named dairy cheeses escaped some ingredient patterns. Ingredient classifier V3 detects them. Rice/glass noodle alternatives are not rejected merely because a recipe title says noodles. New detection does not certify absence, packaged labels or cross-contact safety. [Crabmeat source](https://panlasangpinoy.com/tortang-talong-crabmeat-eggplant-omelet-crab/), [pasta source](https://panlasangpinoy.com/chicken-pasta-alfredo-recipe/).

3. Marinades, condiments and identified sides could be scaled into whole primary slots. Effective/request-time and future import applicability now exclude these component-only recipes; identified desserts/snacks such as Carioca, Binatog and Ginataang Mais stay SNACK-only. The data repair also removes stale primary-slot declarations, including older dessert metadata already narrowed by existing runtime guards. Ordinary chicken dishes and pasta containing sauce remain eligible. [Marinade](https://panlasangpinoy.com/recipe-for-barbecue-chicken-marinade/), [Home Fries](https://panlasangpinoy.com/home-fries-recipe/), [toasted garlic](https://panlasangpinoy.com/how-to-make-toasted-garlic/).

4. Tortilla Española’s unusual macro values match the publisher; copying them again would not correct the serving/nutrition discrepancy. Shrimp and Vegetable Fried Rice supplies no recipe yield and shows whole-recipe-scale nutrition as one serving. Both retain their original values and are retired from source selection pending review. Future imports preserve these holds. No replacement nutrient values were invented. [Tortilla source](https://panlasangpinoy.com/tortilla-espanola-potato-omelet-recipe/), [shrimp fried-rice source](https://panlasangpinoy.com/shrimp-and-vegetable-fried-rice/).

5. Changed source identities get a new content signature. Imported library variants get updated signatures/revisions, STALE evidence and invalidation audit rows; old profile approvals are flagged and active condition clearances suspended. Nutritionist-authored derivatives retain their ingredient lists and require fresh review. Repair does not fabricate reviewer IDs, certification or clinical policy thresholds.

## Verification and coordination

- Separate database: `kainara_catalogue_repair`, task-owned localhost port 55478. Migrated an empty database and copied recipe/food references only: no patients, staff accounts, clinical clearances, approvals or plans. Independent audit uses its own database on port 55479, which was not changed. Owner-authorized messages notified that chat before shared code changes and before development mutations.
- Full isolated repair and actual-database invariant probes passed: whole-catalogue idempotence; every original macro, yield and ingredient quantity unchanged; omelet projection contains 1.5 eggs and detects EGGS; component slots removed; two source holds retained; imported variants invalidated; unconsumed proposals cancelled; consumed history preserved; stale compare-and-swap attempts roll back without further changes. Synthetic fixtures are software verification, not clinical approval.
- Backend suite: 777 passed plus one existing TODO; all six focused source-repair regression tests passed. Backend production build, recipe-audit TypeScript, changed-file ESLint, formatting, architecture limit and whitespace checks passed. No frontend production code changed.
- Default repair command is read-only/dry-run. Applying requires an exact isolated/development target acknowledgment and audit-coordination acknowledgment; recipe backups are ignored local files. Each recipe repair is a serializable transaction with governance locking, source/library compare-and-swap checks and audit events.

## Remaining evidence limits

The 1,100 existing demo nutrient estimates were not converted into measured facts. Remaining unmeasured/ambiguous ingredients, source nutrition gaps, clinical policies, phosphorus evidence and human certification still require legitimate evidence/review. Zero fully reusable certifications in the coverage scan cannot be fixed by labeling raw recipes APPROVED. See [coverage report](MEAL_CATALOGUE_COVERAGE_2026-10-06.md) for the rerun across 166 cases. No live Gemini calls or new member journeys were run by the catalogue repair.
