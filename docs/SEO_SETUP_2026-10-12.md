## Implemented

- One shared public-page catalogue supplies search titles, descriptions and canonical URLs for the homepage, pricing, documentation and RND application. Hydrated browser titles use the same catalogue, preserving private workspace unread counts.
- The homepage identifies Kainara through `WebSite` and `Organization` structured data, its real logo and primary domain. It does not invent ratings, reviews, medical outcomes or contact details.
- A four-page sitemap excludes private routes, account flows and redirect aliases. Production robots.txt points to it. Local development and Vercel previews do not opt into indexing.
- Account, onboarding and member/RND/admin workspace HTML inherit noindex. Production HTML remains crawlable so Google can read that directive; authentication continues to protect records. Robots instructions are not an access-control mechanism.
- Public pages have a branded 1200 × 630 sharing image. The documentation opening chapter is present before JavaScript runs. The pricing page has a semantic H1 while embedded pricing keeps its H2 default. Existing layouts are preserved.
- An optional server-side `GOOGLE_SITE_VERIFICATION` value supports Google's HTML-tag method; no verification token has been entered.

## Step-by-step Google setup

### Before you start

Have the owner's Google account and access to the service managing `kainara.site` DNS. The DNS provider has not been confirmed in this record; hosting on Vercel does not establish where DNS is managed.

The website SEO release is already live. Use these exact addresses:

| Purpose | Address |
|---|---|
| Domain property | `kainara.site` |
| Homepage to inspect | `https://www.kainara.site/` |
| Sitemap to submit | `https://www.kainara.site/sitemap.xml` |

### Step 1 — Open Search Console

1. Open [Google Search Console](https://search.google.com/search-console/welcome).
2. Sign in with the Google account that will manage Kainara.
3. If you see an existing property, open the property selector at the upper left and select **Add property**. Otherwise, use the initial property setup screen.

### Step 2 — Add the website

1. Choose **Domain** for the website property.
2. Enter `kainara.site`. Do not add `https://`, `www` or a slash.
3. Click **Continue**. Keep the verification instructions open.

This property includes the apex and www addresses. [Google's property setup instructions](https://support.google.com/webmasters/answer/34592?hl=en).

### Step 3 — Add the verification record

1. Select **TXT** in Google's verification instructions and copy the supplied value.
2. In the DNS provider, open the DNS records for `kainara.site` and add a record:

| Field | What to enter |
|---|---|
| Type | `TXT` |
| Name / Host | Root domain: `@` or blank, according to the provider's instructions |
| Value / Content | The complete value Google supplied, beginning `google-site-verification=` |
| TTL | Provider default |

3. Save. Preserve the existing website and email records.

### Step 4 — Verify ownership

1. Return to Search Console and click **Verify**.
2. After success, open the property. Keep the TXT record permanently.
3. If verification fails, check the provider, root record and copied value. DNS propagation can take days; wait and retry.

Steps 3–4 follow [Google's ownership verification instructions](https://support.google.com/webmasters/answer/9008080?hl=en).

### Step 5 — Submit the sitemap

1. Open [Kainara's sitemap](https://www.kainara.site/sitemap.xml). Expect XML listing the homepage, pricing, docs and RND application.
2. In Search Console, select the `kainara.site` property.
3. Open **Sitemaps** under **Indexing**.
4. In **Add a new sitemap**, enter `https://www.kainara.site/sitemap.xml` and click **Submit**.
5. Look for **Success**. If another status appears, open its row for details.

Success means Google read the sitemap; it does not mean all pages are indexed. Private member, RND and admin pages are intentionally absent. [Google's sitemap instructions](https://support.google.com/webmasters/answer/7451001?hl=en).

### Step 6 — Request homepage indexing

1. Paste `https://www.kainara.site/` into the URL inspection field at the top of Search Console and press **Enter**.
2. Read the current indexing status.
3. Click **Test live URL** to check the currently published page.
4. If the live page is eligible and indexing is needed, click **Request indexing**.
5. Record the request date. Pricing and docs can be inspected the same way.

The live test checks eligibility, not whether Google has already indexed the page. [Google's URL inspection instructions](https://support.google.com/webmasters/answer/9012289?hl=en).

### Step 7 — Check search visibility later

1. Revisit homepage URL inspection to check whether Google reports it indexed.
2. Open **Pages** under **Indexing** to investigate public-page exclusions.
3. Open **Performance → Search results** when data is available. Check queries containing **Kainara**, impressions and clicks. [Google's Performance report guide](https://support.google.com/webmasters/answer/7576553?hl=en).
4. Search Google for **Kainara**, without `.site`, to see the user-facing result.

Google controls indexing and ranking. Processing can take days or weeks; requesting repeatedly does not speed it up, and no first-place result is guaranteed. [Google's recrawl guidance](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl).

### Troubleshooting

| What you see | What to do |
|---|---|
| Verification TXT record not found | Recheck Step 3, then allow time for DNS propagation. |
| Sitemap could not be fetched | Open the sitemap link directly, check the submitted address and read the report's error details. |
| Public page cannot be indexed | Check the live inspection result and record its specific reason before changing code. |
| Login or private workspace excluded | Expected: these routes have noindex. |
| Eligible page still awaiting indexing | Monitor its inspection status; repeated requests do not accelerate crawling. |
| URL-prefix sitemap field already displays the website address | Enter only `sitemap.xml` so the address is not repeated. |

### Alternative — If DNS access is unavailable

1. Add a **URL-prefix** property for `https://www.kainara.site/` and choose **HTML tag** verification.
2. Copy only the tag's `content` value into the existing `GOOGLE_SITE_VERIFICATION` setting.
3. In Vercel project **nutrimindv1**, open **Settings → Environment Variables**, save that value for **Production**, then redeploy the reviewed production release. Environment changes require a new deployment. [Vercel environment variable guide](https://vercel.com/docs/environment-variables).
4. Confirm the homepage source contains the matching verification tag, then click **Verify** in Google. Retain the setting.
5. Continue with Steps 5–7 using this property.

This fallback uses the existing frontend support. The preferred DNS procedure needs no application setting or redeployment. A full development release remains a separate action because earlier local application updates are not included in the published SEO release.
