# Independent audit findings: repair review — October 6, 2026

Reviewed the independent auditor's original and continuation findings against executable code and the latest engineering record. The auditor used frozen baselines; this repair changes the shared development checkout. Its scripts, report, evidence and isolated database on port 55479 are preserved.

## Decisions and repairs

| Finding                                                                                  | Decision                                                          | Repair                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| IND-001: changed email inherits verification                                             | Confirmed defect                                                  | Normalize/validate account settings in a service. An inbox change atomically clears verification, replaces the OTP/expiry and resets attempts. Send proof only to the new inbox after commit. Delivery failure leaves the inbox unverified and permits the ordinary resend flow. Same normalized email preserves proof. Frontend updates verification state so the existing guard opens verification.                          |
| IND-002: malformed email persisted                                                       | Confirmed defect                                                  | Reject malformed/blank/non-string email, invalid credential types and invalid password strength before writing. Database uniqueness errors return a typed account error. A failed combined email/password request commits neither field.                                                                                                                                                                                       |
| IND-003: concurrent water removals lose a decrement                                      | Confirmed defect                                                  | Add/remove/reset lock the same User row before reading or writing hydration entries. Return the resulting day total within that transaction. Preserve Manila day boundaries and existing entry-size constraints.                                                                                                                                                                                                               |
| IND-004: scheduled status reset leaves daily totals stale                                | Confirmed defect                                                  | After the guarded scheduled log upsert, recalculate an existing daily aggregate in the same transaction for that meal's scheduled Manila day. DONE/PENDING/SKIPPED transitions update calorie/macronutrient/adherence history. Daily cron aggregation shares the user/profile lock so it cannot commit an older total over a reset. Existing ownership and meal-clearance checks remain enforced.                              |
| IND-005: repeated concurrent publication duplicates activation history                   | Confirmed defect                                                  | Lock the reference source inside the transaction, reload release/source state and validate the transition under that lock. Publication and rollback serialize across releases of the same source. Repeat attempts return HTTP 409 without extra activation/audit rows.                                                                                                                                                         |
| IND-006: partially populated plan does not discover newly certified missing-slot sources | Recovery feature gap; not accepted as a regression in this repair | The current queue deliberately allows corpus re-selection only for empty failed cycles. The latest engineering record explicitly limits that repair to empty cycles. Preserve populated/frozen/shopped work and existing safety gates. A future missing-slot recovery feature must select and validate new sources without superseding retained plates; this report does not claim that feature is implemented.                |
| IND-007: password change keeps other refresh sessions                                    | Policy accepted and implemented                                   | A successful current-password change revokes all persisted refresh sessions, clears outstanding reset proof and the browser refresh cookie, and requires a fresh sign-in. Login rechecks the password hash under the same account-row lock before creating a session, blocking a login verified before the change from creating a refresh session afterward. Google-only accounts cannot set a password through this endpoint. |

Additional identity races discovered during repair: OTP verification/resend and reset-token issuance now condition their writes on the inbox and token they read. A linked Google subject can verify only the same authoritative contact inbox, using a conditional write. A response for an old inbox cannot mark a changed contact address verified. Provider subject links are retained.

Password-session revocation uses the existing refresh-session table. Already issued access JWTs retain their existing maximum 15-minute lifetime; this change does not claim immediate revocation of every bearer token. The changing browser clears its client session/cache through the ordinary logout flow. Real OTP delivery and Google cryptography remain provider verification tasks.
