# Nara authentication mascot

Generated on October 7, 2026 with Codex's built-in image generation tool, using the owner's supplied Nara tanod portrait. Transparency was enabled on both calls. No runtime image generation or external asset requests are used by the app.

- `directions.png`: original accepted 3×3 direction sheet, viewer left/right order.
- `reactions.png`: original accepted 3×3 expression sheet, using the directions as its reference.
- Served atlases: `../../public/mascots/nara-tanod-directions.webp` and `nara-tanod-reactions.webp`.
- Integration: `src/components/auth/AuthMascot.tsx`, supplied by AuthShell to all shared authentication screens.

## Rebuild

Install the owner's requested `nilbuild/page-mascot` skill. From `frontend`, run its `scripts/mascot.py nara-tanod --skip-generate` with Python containing Pillow, NumPy and SciPy. The installed skill and isolated Python packages are local tooling, not app dependencies. The app pins `page-mascot` to 0.1.0. See the [upstream source](https://github.com/nilbuild/page-mascot) for the builder and component.

The first generation attempt was rejected for overlapping framing. The second pair passed screening and packing: 0.00 px vertical drift at 140 px, 80.9% palette agreement, 0.3% shoulder-width difference, no detected cell-edge contacts. A separate agent checked all direction orientations and integration. Browser screenshots at the actual 120 px size were inspected on light and dark backgrounds; transparent image viewers exaggerate near-transparent pixels that are invisible when composited normally. Minor visual limitation: bun/ribbon placement differs between the upper-right and other right-facing poses.

Browser checks cover all eight pointer directions, keyboard reaction without form submission, mobile taps/overflow, live reduced-motion changes, all shared authentication routes, responsive form reachability, existing credential submission and recovery behavior. Reduced motion renders a static central portrait. The component does not inspect inputs, passwords or authentication state.

The subsequent owner-requested layout replaces the tile hero, marketing text and badges with a centered Nara. After the owner requested a much larger portrait, the desktop stage uses a tall 2:3 shape (up to 640 px wide) and doubles the inner canvas to remove transparent gutters. The stage is constrained by panel width and viewport height and clipped to keep it away from the form; mobile keeps a 160 px canvas above the form heading. Light/dark browser screenshots were inspected at the enlarged size. The 20 authentication checks passed for the initial hero layout; the eight relevant mascot and form browser checks passed again after enlargement. The same source art is reused; enlargement can soften the raster detail.
